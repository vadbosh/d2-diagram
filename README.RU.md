# d2-diagram

Попросишь ассистента нарисовать схему архитектуры — получишь одно из двух: блок
Mermaid, который рендерится, но выглядит как все остальные блоки Mermaid, либо
несколько сотен строк SVG с расставленными вручную координатами, которые больше
никто никогда не поправит.

Этот скилл идёт третьим путём. Ассистент пишет несколько десятков строк на
[D2](https://d2lang.com), координаты считает движок раскладки, рядом с исходником
коммитится PNG. Схема живёт в git, меняется тем же pull request, что и код, и её
diff можно прочитать.

Работает с Claude Code, Opencode и Codex на Linux и macOS.

[English version](README.md)

## Зачем

Схема устаревает быстрее любой другой документации, потому что поправить её
дороже, чем не заметить. Две привычки делают только хуже:

- **Картинка без исходника.** SVG, нарисованный руками, нельзя изменить, не
  проделав работу заново. Поэтому его и не меняют — и через месяц он описывает
  систему, которой больше нет.
- **Исходник, который никто не читает.** Пятьсот строк `<path d="M…">` в pull
  request рецензент не разбирает. Изменение проходит непроверенным.

D2 решает обе задачи тем, что разделяет их. Добавить компонент — одна строка:

```d2
private: Private subnets {
  eks: EKS node group
  rds: RDS Postgres {shape: cylinder}
}

internet -> public.alb: ":443"
public.alb -> private.eks: ":8080"
private.eks -> private.rds: ":5432"
```

Координаты — не твоя забота, их считает `dagre` или `elk`. В pull request видно
`+ rds: RDS Postgres`, а не стену чисел.

## Что скилл добавляет поверх D2

D2 — это язык, а скилл — рабочая практика вокруг него, и почти всё в ней выросло
из того, что однажды пошло не так:

- **Палитра в одном файле.** Tailwind slate, синий хребет, оранжевый акцент;
  каждая схема подключает её строкой `...@theme`. Поменял один файл — изменилось
  оформление всех.
- **PNG, и никогда SVG, если картинка идёт на GitHub.** Встроенный SVG виден, но
  клик по нему приводит на страницу, которую GitHub рендерить отказывается: у
  читателя остаётся мелкая картинка, которую нельзя увеличить. Скилл встраивает
  PNG, обёрнутый ссылкой на себя, а SVG держит как промежуточный файл в `/tmp`.
- **Никаких markdown-подписей.** Блок `|md` компилируется в `<foreignObject>`, а
  SVG с ним GitHub отвергает целиком — и выглядит это как сломанный файл, а не
  как вопрос оформления.
- **Пропорции как обязательная проверка.** Колонка README — примерно 900 пикселей,
  поэтому холст 4:1 нечитаем, каким бы хорошим ни было содержание. Смени
  `direction:` и посмотри на `viewBox`.
- **Рёбра берутся из кода, а не из памяти.** Из блоков `terraform_remote_state`,
  из `madge`, из `pyreverse`. Граф зависимостей, нарисованный по памяти, врёт в
  тот день, когда кто-то добавил импорт.
- **Честная граница.** D2 не нарисует диаграмму Венна, пирамиду, radar и вообще
  ничего, где смысл несёт координата или площадь. Скилл говорит об этом прямо и
  называет, чем это делать вместо него, — чтобы никто не потратил час, выгибая
  его в воронку.

## Установка

```bash
git clone https://github.com/vadbosh/d2-diagram.git
cd d2-diagram
./install.sh              # во все найденные IDE
./install.sh --dry-run    # показать, что будет сделано
```

Скилл ставится в `~/.claude/skills/d2-diagram`,
`~/.config/opencode/skills/d2-diagram` и `~/.codex/skills/d2-diagram` — в те из
них, которые существуют. Не установленный ассистент пропускается, а не
создаётся.

Без бинарника `d2` скилл бесполезен, поэтому его отсутствие установщик
предлагает исправить: определяет последний релиз под твою ОС и архитектуру и
распаковывает его в `~/.local/bin`. В терминале сначала спрашивает, по умолчанию
«нет»; `--with-d2` пропускает вопрос, `--no-d2` убирает предложение.

У разработчиков есть и однострочник `curl … | sh`. Здесь он не используется и не
рекомендуется: подать скачанный скрипт прямо в оболочку — значит выполнить всё,
что отдал сервер, а тот же результат достигается одним архивом:

```bash
tag=$(curl -fsSL https://api.github.com/repos/terrastruct/d2/releases/latest \
      | sed -n 's/.*"tag_name" *: *"\([^"]*\)".*/\1/p' | head -1)
curl -fsSL -o d2.tar.gz \
  "https://github.com/terrastruct/d2/releases/download/$tag/d2-$tag-linux-arm64.tar.gz"
tar xzf d2.tar.gz
install -m 0755 "d2-$tag/bin/d2" ~/.local/bin/d2
```

Подробности, флаги и проверка — [docs/install.ru.md](docs/install.ru.md).

## Как пользоваться

Вызывать ничего не надо — скилл срабатывает на саму просьбу. «Нарисуй
архитектуру этого модуля», «покажи импорты в `src/`», «схема пути запроса» —
всё это доходит до него. Он читает настоящий исходник, а не вспоминает, пишет
`<name>.d2`, собирает `<name>.png` и показывает картинку.

```
docs/diagrams/
├── theme.d2            общие цвета и стили линий
├── cluster.d2          исходник — его правят и рецензируют
└── cluster.png         то, на что ссылается README
```

## Тесты

```bash
./tests/test_render.sh
```

Собирает каждый пример из поставки, проверяет, что ни один не породил
`<foreignObject>`, валидирует тему и сверяет, что все описанные в скилле стилевые
классы действительно существуют. Без `d2` набор пропускается, а не падает.
