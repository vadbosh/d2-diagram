# Устройство

Почему инструмент — D2, почему коммитится PNG и где весь подход перестаёт
работать. Каждое решение принято против конкретной неудачи, и неудача названа.

## Почему не Mermaid

Mermaid рендерится нативно внутри GitHub и GitLab, бинарника не требует, и для
блок-схемы из пяти узлов это правильный ответ. Дальше него схему выталкивают две
вещи:

- **Вид.** Mermaid 11 умеет заметно больше прежнего — `layout: elk`,
  `look: handDrawn`, полный `themeVariables`, — но что именно получится, решает
  версия рендерера, встроенная в форж. GitLab сейчас поставляет mermaid 11.13,
  где `look` принимает только `classic` и `handDrawn`; схема, написанная под
  более новый `look`, молча отрисуется старым. Ты оформляешь то, чем не
  управляешь.
- **Раскладка.** Всё, где есть контейнеры, перекрёстные связи и больше десятка
  узлов, превращается в борьбу с рендерером.

Правило простое: Mermaid — когда рендерер чужой, а схема маленькая. D2 — когда
схема живёт и её сопровождают.

## Почему не рукописный SVG

Есть целый класс инструментов, где модель пишет SVG напрямую. Они умеют то, чего
D2 не умеет, — пирамиды, диаграммы Венна, editorial-фигуры, — и в презентации
выглядят лучше. Цена в том, что артефакт и исходник здесь один и тот же файл:
пятьсот строк координат. Такое не рецензируют в pull request и не правят через
месяц — такое перерисовывают.

D2 разделяет эти две роли. Сорок строк исходника читает и меняет человек,
картинка генерируется.

Есть и текущая цена. Скилл такого рода загружает десятки килобайт инструкций и
выдаёт сотни строк SVG. Этот загружает несколько килобайт и выдаёт сорок строк
D2 — примерно на порядок меньше на схему, что заметно, когда схемы рисуются
регулярно, а не изредка.

## Почему коммитится PNG

Решение неочевидное. SVG лучше как формат: вектор, компактный, самодостаточный.
И всё равно коммитить его нельзя, по одной вполне конкретной причине.

**GitHub отказывается показывать страницу SVG-файла.** Встроенная в README
картинка видна, но клик по ней приводит на страницу с «Unable to render code
block» — и на вкладке Code, и на Preview. У читателя остаётся миниатюра,
вписанная в ширину колонки, и никакой возможности её увеличить; для схемы плотнее
пяти прямоугольников это означает, что она декоративная.

Поэтому коммитится PNG, встроенный ссылкой на самого себя:

```markdown
[![Cluster A](docs/diagrams/cluster-a.png)](docs/diagrams/cluster-a.png)
```

Клик открывает просмотрщик GitHub в полном разрешении. PNG собирается в двойном
масштабе, чтобы этот просмотр был чётким.

SVG остаётся только промежуточным шагом: `d2` собирает его, `rsvg-convert`
растеризует, PNG сохраняется, а SVG умирает в `/tmp`. Там, где `d2 x.d2 x.png`
работает напрямую, SVG не появляется вовсе.

Вторая причина не коммитить его: два собранных файла, претендующих на одну и ту
же схему, разойдутся при первой же пересборке одного из них.

## Почему палитра лежит в одном файле

`theme.d2` объявляет стилевые классы, каждая схема подключает его строкой
`...@theme`. Это не аккуратность, а разница между «поменять оформление
репозитория» и «поменять оформление одной схемы». Набор классов намеренно
небольшой и смысловой, а не визуальный: `spine` — те один-два узла, которые
читают первыми, `focus`/`hot` — то, что меняется прямо сейчас, `ext` — то, чем ты
не управляешь, `dep`/`read`/`cut` — виды связи. Схема, написанная в этих
терминах, остаётся читаемой при смене палитры под ней.

## Пропорции — это вопрос правильности, а не вкуса

Колонка README — примерно 900 пикселей. Значит, холст 2:1 отрисует шрифт в 20
пикселей примерно семью, а холст 4.6:1 превратится в декоративную ленту. Это не
оформление, которое поправят потом: нечитаемая миниатюра — сломанная схема.

Лечится обычно одним словом. Замена `direction: right` на `direction: down`
превратила схему мониторинга 3521×770 в 1128×2060: то же содержание, тот же
исходник, читается прямо в тексте. Смотреть надо на `viewBox` после сборки, а не
на картинку в голове.

## Дефект, которого нет в исходнике

Где что окажется, решает движок раскладки. В этом весь смысл D2 — и по этой же
причине целый класс поломок в `.d2` не виден вообще: исходник правильный,
картинка нет, а `d2 validate` не к чему придраться.

Повторяется вот что. Заголовок контейнера D2 ставит по центру верхней границы, а
входящую стрелку движок заводит туда же. Стрелка проходит сквозь текст. На одной
здешней схеме она заменила собой тире в `Kubernetes — namespace gateway-system`,
и читалось это как знак препинания.

Сменить движок не помогает: замерено на 0.7.1 на схеме, собранной ради этого
столкновения, — и `dagre`, и `elk` рисуют стрелку через заголовок. Помогает
другое: освободить середину контейнера, потому что стрелка приходит именно
туда. Короче заголовок, `label.near: top-left`, чаще и то и другое сразу.

Глазами это не ловится. Четыре схемы галереи разглядывал в полный размер тот,
кто час перед этим занимался ровно этим дефектом; две из четырёх он объявил
чистыми, и обе были пробиты. В таком масштабе линия в два пикселя поперёк
подписи не видна.

Поэтому считается арифметикой. `scripts/check_labels.py` обходит SVG, меряет
каждую подпись узла и контейнера тем шрифтом, которым картинка и будет
нарисована, и находит стрелки, проходящие сквозь них. Лежит внутри `skill/`, а
не рядом с остальными скриптами: в ассистента уезжает только каталог скилла, и
проверка, оставленная в репозитории, была бы проверкой, которой у рисующего
агента нет.

**Она читает геометрию и больше ничего.** Схема может её пройти и при этом
рисовать связь, которой не существует, или не рисовать ту, ради которой всё
затевалось. Для этого и нужно читать исходники перед тем, как рисовать, — и это
единственное здесь, чего не проверяет ни один инструмент.

## Где подход заканчивается

D2 расставляет узлы движком раскладки. **Всё, где смысл несёт координата или
площадь, ему недоступно**, и никакими стилями это не обходится.

| Умеет сам | Возможно через grid | Не может |
|---|---|---|
| архитектура, поток, sequence, state, классы, ER | квадрант, матрица 2×2 | Венн — круги не наложить |
| дерево, оргструктура, вложенность, слои | матрица сравнения | radar / spider |
| swimlane, процесс, поток данных, путь запроса | | пирамида, воронка — фигуры «треугольник» нет |
| циклы и петли обратной связи | | bar, line, scatter, gantt — нет ни осей, ни примитивов графика |
| | | treemap — площади не сделать пропорциональными |

`shape: triangle` отклоняется сразу: `invalid shape, can only set "triangle" for
arrowheads`.

Для правого столбца нужен инструмент, сделанный под это, — скилл, пишущий SVG
руками, для editorial-фигур, или библиотека графиков, если это действительно
график по числам. Выгибание D2 в воронку стоит часа и даёт результат хуже
обоих вариантов.
