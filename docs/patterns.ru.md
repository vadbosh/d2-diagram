# Приёмы и ловушки

## Связи берутся из кода, а не из памяти

Граф зависимостей, нарисованный по памяти, врёт в тот день, когда кто-то добавил
импорт. Его надо извлекать.

**Terraform.** Граф между корневыми модулями уже записан: каждое чтение чужого
стейта — это блок `terraform_remote_state`.

```bash
rg -n 'data "terraform_remote_state" "' --glob 'ext.data.tf' .   # связи
rg -o 'resource "helm_release" "[a-z0-9_-]+"' <layer>/*.tf        # что ставит слой
rg -n 'module "' <layer>/*.tf                                     # модули по слоям
```

Каждый корневой модуль рисуется отдельным контейнером, внутри — три-пять узлов
на то, чем он владеет, и по одной стрелке на каждое чтение чужого состояния.
Порядок применения и связность после этого видны на картинке.

**Код.**

| Стек | Чем достать связи | Запускалось здесь? |
|---|---|---|
| JS / TS | `madge --json --extensions ts,tsx src` | да — 541 модуль, 1129 рёбер на живом проекте |
| JS / TS | `depcruise --output-type json --no-config src` | да, с оговоркой (ниже) |
| Python, модули | `pydeps <путь-к-пакету> --show-deps --no-output --no-show` | да |
| Python, классы | `pyreverse -o dot -p ИМЯ <путь>` (идёт с pylint) | да — 51 модуль, 94 импорта |
| Go | `go list -deps ./...`, `go mod graph` | да |
| Java | `jdeps -verbose:class app.jar` | JDK здесь нет |
| PHP | `deptrac analyse --formatter=json` | composer здесь нет |

Каждый отдаёт JSON или dot; связи переносятся в строки D2, раскладку считает
движок.

Четыре ловушки, каждая встречена при запуске:

**dependency-cruiser, установленный глобально, отдаёт пустой граф для TypeScript.**
`"modules": []`, и он сам объясняет почему: ему нужно быть локальной
devDependency, чтобы дотянуться до транспиляторов проекта. Тот же глобальный
бинарник на чистом JavaScript отработал верно — 2 модуля, 1 связь, — так что
пустой результат здесь означает неверную установку, а не ответ. madge, тоже
глобальный, прочитал тот же TypeScript-проект без единой жалобы.

**Циклы находит `madge --circular`**, а `--json` отдаёт граф и про циклы молчит.
Запускать стоит обе.

**pydeps хочет путь, а не имя модуля.** На `pydeps json` он отвечает
`No such file or directory: 'json'`; указывай каталог пакета.

**pyreverse пишет два файла** — `classes_<имя>.dot` и `packages_<имя>.dot` — в
текущий каталог, а не в stdout. У пакета без классов первый останется пустым, и
это выглядит как сбой, но им не является.

Пустой вывод `go mod graph` — та же история: он перечисляет требования *модулей*,
а внешних у модуля может не быть. Про пакеты отвечает `go list -deps ./...` — 123
штуки на модуле с двумя импортами.

**Живая инфраструктура.** Когда вопрос не «что написано в конфигурации», а «что
реально развёрнуто», начинать надо с состояния: `terraform state list` даёт
перечень, `terraform show -json` — атрибуты и зависимости между ресурсами. Оба
идут в составе Terraform.

Сторонние инструменты вроде `inframap` строят граф прямо из tfstate с учётом
провайдера. Возможно, они тебе подойдут; в этом репозитории ими ничего не
делалось, так что считай это указателем, а не рекомендацией.

## Как убирать узлы

Чаще всего инфраструктурная схема становится нечитаемой из-за однотипной связи,
повторённой много раз.
Каждый корневой модуль Terraform пишет в один и тот же бэкенд S3 — семь стрелок
в общий прямоугольник «S3 backend» говорят ровно то же, что одна строка
подзаголовка, но стоят семи пересечений. То же с обёрткой «AWS» вокруг всего, с
актёром «пользователь» у левого края и с ролями IAM на каждый ресурс.

Ориентир: один экран, без пересечений, меньше примерно 25 листовых узлов. Больше
— это две схемы.

## Фигуры, которые стоит помнить

```d2
db: {shape: cylinder}          # хранилище
q: {shape: queue}              # очередь или поток
c: {shape: cloud}              # то, чем управляют не здесь
t: {shape: text}               # подпись без рамки — так делаются заголовки
```

Ещё есть `class` и `sql_table` (ниже), `sequence_diagram`, `person`, `hexagon`,
`package`, `step`, `callout`, `stored_data`.

## Классы и модели данных

```d2
Record: {
  shape: class
  +zone_id: str
  +to_change_batch(): dict
  -validate(): bool
}
Client -> Record: returns
```

```d2
dns_record: {
  shape: sql_table
  id: bigint {constraint: primary_key}
  zone_id: varchar(32) {constraint: foreign_key}
  set_identifier: varchar(64) {constraint: unique}
}
route53_zone.id <-> dns_record.zone_id: "1 : N"
```

Стрелку можно прицепить к конкретной колонке — именно поэтому внешний ключ
читается, а не остаётся линией между двумя прямоугольниками.

## Ловушки

**Блоки `|md` запрещены везде.** Markdown-подпись компилируется в
`<foreignObject>`, а SVG с ним GitHub рендерить отказывается: на странице файла
«Unable to render code block», картинки нет вовсе. Заголовок пишется обычной
строкой в кавычках с `\n` на узле `shape: text`.

**`classes` — зарезервированное слово.** Назовёшь так контейнер — и всё внутри
будет разобрано как объявление стилевых классов. Ошибка при этом сбивает с толку:
`... is an invalid class field, must be reserved keyword`. То же касается `vars`,
`layers`, `scenarios`, `steps`, `direction`.

**Сигнатура метода разбирается.** Скобки в типе возврата ломают файл:
`list[Record]` не проходит. Закавычь — `"list of Record"` — или упрости.

**`;` — разделитель инструкций.** Незакавыченная подпись с точкой с запятой
распадается на два узла. Подписи со знаками препинания надо закавычивать.

**Верить коду возврата, а не наличию файла.** При ошибке D2 оставляет после себя
недособранный файл, так что «файл появился» не доказывает ничего.

**Экспорт в PNG ломается на машине, а не в схеме.** `d2 x.d2 x.png` сначала
скачивает драйвер Playwright, и эта загрузка мертва на всех платформах:
`playwright.azureedge.net` отключён, а заменивший его хост отвечает
перенаправлением, по которому Go-клиент внутри D2 не идёт. Собирай SVG в `/tmp`
и растеризуй его через `rsvg-convert` (librsvg, `apt install librsvg2-bin`):

```bash
d2 cluster.d2 /tmp/cluster.svg
rsvg-convert -z 2 /tmp/cluster.svg -o docs/diagrams/cluster.png
```

**librsvg надо указать шрифт.** D2 встраивает шрифт как data-URL в `@font-face`,
а librsvg такие шрифты не читает — и меряет подписи тем шрифтом, который нашёлся
в системе, после чего они перестают помещаться в рамки, рассчитанные D2: под
DejaVu `unit_price_cents` налез на `bigint`. Встраивается урезанная копия Source
Sans Pro — только использованные знаки, переименованная под каждую схему.
Поэтому поставь Source Sans (`apt install fonts-adobe-sourcesans3`) и перед
растеризацией переведи на него четыре текстовых класса. `render.sh` так и
делает: имя семейства закавычено только в правилах классов и никогда в блоках
`@font-face`, поэтому `sed` здесь не промахнётся.

**Headless-браузер по-прежнему работает.** `render.sh` берёт его, когда librsvg
в системе нет, а `D2_BROWSER` заставляет использовать именно его. Это просто
более тяжёлый путь — целый браузер ради одной конвертации.

**ImageMagick заменой не служит.** `convert x.svg x.png` формально работает и
выбрасывает все заливки, отдавая серую картинку, — для проверки схемы бесполезно.

**Смотреть на собранное до того, как о нём отчитываться.** Непросмотренная схема
не проверена: движок раскладки выдаёт неожиданное и из правильного исходника.
