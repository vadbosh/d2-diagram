# Установка

## Что и куда ставится

По одному каталогу на ассистента, внутри — сам скилл и его примеры:

| Ассистент | Путь |
|---|---|
| Claude Code | `~/.claude/skills/d2-diagram/` |
| Opencode | `~/.config/opencode/skills/d2-diagram/` |
| Codex | `~/.codex/skills/d2-diagram/` |

Формат у всех трёх одинаковый, поэтому установка — обычное копирование каталога.
За пределами `$HOME` ничего не трогается, профиль оболочки не правится.

```bash
./install.sh
```

Ассистент, у которого каталога скиллов нет, отмечается как пропущенный.
Установщик его не создаёт: пустое дерево, которое ассистент никогда не прочитает,
хуже, чем ничего, — оно выглядит установленным.

## Флаги

| Флаг | Что делает |
|---|---|
| `--dry-run` | печатает все действия, ничего не меняет |
| `--ide claude` | ставит только в одного ассистента (`claude`, `opencode`, `codex`) |
| `--skills-dir D` | ставит в `D` вместо определённого пути |
| `--with-d2` | заодно поставить бинарник d2, не спрашивая |
| `--no-d2` | бинарник не трогать, только сообщить, есть ли он |
| `--bin-dir D` | положить бинарник в `D` вместо `~/.local/bin` |
| `-h`, `--help` | справка |

`--skills-dir` нужен при нестандартной раскладке — переносимый checkout, образ
контейнера, ассистент, установленный под префиксом.

## Повторный запуск

Идемпотентен. Установщик сравнивает поставляемый скилл с установленным и ничего
не делает, если они совпадают:

```
[claude] already current — ~/.claude/skills/d2-diagram
[opencode] already current — ~/.config/opencode/skills/d2-diagram
[codex] already current — ~/.codex/skills/d2-diagram
```

Если различаются, прежняя копия сначала сохраняется — в
`~/.local/state/d2-skill-backups/<ide>-<timestamp>/`, и намеренно **не** рядом
со скиллом.

Причина конкретная, а не вопрос вкуса. Ассистент читает каталог скилла целиком,
поэтому `SKILL.md.bak.1786446628`, лежащий рядом с `SKILL.md`, загружается как
часть скилла, а копия целого каталога, положенная по соседству, — как второй
скилл. И то и другое случалось на живых машинах. Другое место задаётся
переменной `D2_SKILL_BACKUP_DIR`.

## Бинарник d2

Скилл пишет файлы `.d2`, но без бинарника ничего не соберётся. Поэтому его
отсутствие не просто сообщается, а предлагается исправить:

```
d2 is NOT on PATH — the skill can write .d2 files but nothing will render.
Download and install the latest d2 into ~/.local/bin? [y/N]
```

Ответишь `y` — установщик определит последний релиз под твою ОС и архитектуру,
скачает архив, положит бинарник в `~/.local/bin` и напечатает полученную версию.
Если каталога нет в `PATH`, он об этом скажет.

Молча не скачивается ничего:

- в терминале спрашивают, и ответ по умолчанию — «нет»;
- без терминала (CI, конвейер, скрипт развёртывания) не качается ничего, пока не
  передан `--with-d2`;
- `--no-d2` убирает предложение совсем;
- `--dry-run` печатает точный URL, который был бы скачан, и останавливается.

Определяются `linux` и `macos` на `amd64` и `arm64`; все четыре архива текущего
релиза запрошены и отвечают кодом 200, то есть имена, которые собирает
установщик, верны. Для всего остального печатается страница релизов, решение
остаётся за тобой.

На macOS установщик сам предпочитает Homebrew, если находит его: `brew install
d2` сейчас даёт 0.8.1, новее последнего релиза на GitHub, потому что тег v0.8.1
создан без приложенных бинарников. Если brew нет или он упал — установщик
откатывается к релизному архиву, а это 0.7.1.

Откат проверен на Linux подставным Darwin-хостом с падающим brew: скрипт
сообщил об ошибке, определил `macos-arm64`, скачал архив и отказался его
принимать, потому что бинарник не запускается на этой машине —
`installed … but it does not run — wrong build for this machine?`. Сама ветка с
brew на настоящем Маке не запускалась.

Версия берётся из эндпоинта *releases*, а не из списка тегов. Тег может
существовать без приложенных бинарников — ровно такой случай `v0.8.1`, — и
собранный по нему адрес отдаёт 404.

Контрольных сумм рядом с архивами разработчики не публикуют, сверять скачанное
не с чем: вся гарантия — HTTPS до github.com.

У разработчиков есть и однострочник `curl -fsSL https://d2lang.com/install.sh |
sh -s --`. Ни установщик, ни эта документация им не пользуются: подать скачанный
скрипт в оболочку — значит выполнить всё, что сервер отдал в эту минуту, не имея
возможности сначала прочитать. `--with-d2` делает те же три шага, которые ты
сделал бы руками, — а с `--no-d2` их можно сделать руками:

```bash
tag=$(curl -fsSL https://api.github.com/repos/terrastruct/d2/releases/latest \
      | sed -n 's/.*"tag_name" *: *"\([^"]*\)".*/\1/p' | head -1)
curl -fsSL -o d2.tar.gz \
  "https://github.com/terrastruct/d2/releases/download/$tag/d2-$tag-linux-arm64.tar.gz"
tar xzf d2.tar.gz
install -m 0755 "d2-$tag/bin/d2" ~/.local/bin/d2
```

Замени `linux-arm64` на свою платформу: архивы называются `linux-amd64`,
`macos-amd64` и `macos-arm64`.

## Проверка

```bash
d2 --version                 # бинарник на месте
./tests/test_render.sh       # примеры собираются, правила держатся
```

Дальше нужна **новая** сессия ассистента: запущенная уже загрузила свой список
скиллов. Попроси то, на что отвечает схема («нарисуй граф модулей этого пакета»);
если скилл подхватился, в ответ появится `.d2` и собранный `.png`, а не блок
Mermaid.

## Удаление

```bash
./uninstall.sh                     # отовсюду, где он стоит
./uninstall.sh --dry-run
./uninstall.sh --ide codex
./uninstall.sh --skills-dir D      # из D, парно с install.sh
./uninstall.sh --purge             # заодно удалить сохранённые копии
```

Без `--purge` копии остаются. Бинарник `d2` не трогается — этот репозиторий его
не ставил.
